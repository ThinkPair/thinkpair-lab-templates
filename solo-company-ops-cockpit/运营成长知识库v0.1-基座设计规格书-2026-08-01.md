# 降噪实验室｜运营成长知识库 v0.1 基座设计规格书

> 本稿是待用户确认的首版规格，不是已完成产品，也不是市场验证。

## 一句话定位

用运营思维，把“我是谁、我想去哪里、我经历了什么、我是怎么判断的、我做了什么、结果如何”连接成一套能持续更新的个人成长知识库。

核心循环：

```text
认识自己 → 明确方向 → 记录经历与输入 → 形成自己的判断
→ 做出决策与行动 → 留下结果和证据 → 复盘变化 → 更新对自己的认识
```

免费知识库负责人的整体信息和成长循环；19.9元场景看板负责把减肥、英语、内容创作等某一个持续变化的具体事项做成更强的追踪界面。两层不得混写。

## 认知刹车

### 1. 当前优先级冲突

2026-08-01是抖音首播硬节点。今天可以完成基座规格和最小空白骨架，但不能为了“做完整产品”挤掉直播准备、真实开播和用户问题记录。

### 2. 外部陌生人会质疑什么

1. 我为什么不用手机备忘录、飞书或普通Obsidian模板？
2. 为什么一个免费知识库还要安装Obsidian、Claudian、Claude Code和配置API？
3. 打开以后十分钟内我到底得到什么，而不是又获得一堆空文件夹？

### 3. 30—60分钟最小证据动作

只做一个首页、六个用户目录、四份核心模板、两份AI适配入口和一份测试数据；让一个没有接触过本系统的人在十分钟内完成“我的当前成长底稿”。

### 4. 机会成本

- 今天完全不做：群里没有可展示的免费产品骨架。
- 今天做完整包：大概率挤掉首播，并再次陷入插件、皮肤和自动化细节。

## 用户第一次获得什么

用户第一次打开后，不先配置API，不先学文件夹，不先做挑战。

十分钟内完成一份：

```text
《我的当前成长底稿》
```

其中只有六个问题：

1. 我现在是谁，处于什么阶段？
2. 最近最想发生的1—3个变化是什么？
3. 我已经拥有哪些经验、能力、资源和支持？
4. 目前最大的限制和现实条件是什么？
5. 最近有哪些反复出现、需要我判断的问题？
6. 接下来30天，我希望看到什么可观察的变化？

完成后首页自动/手动呈现：当前阶段、成长主题、待判断问题、最近行动、最近结果和待复盘项。

这份底稿是整体个人知识库的入口，不是单一行动看板，也不是固定7天挑战。

## 首页信息架构

首版不做复杂图表，只做六块：

1. **我的当前阶段**：一句话说明我现在在哪里。
2. **正在经营的成长主题**：最多3项，只显示状态，不做细颗粒打卡。
3. **等待我判断的问题**：把未想清楚的问题留在这里。
4. **最近行动**：做了什么，不把计划冒充完成。
5. **结果与证据**：作品、反馈、数据和现实变化。
6. **快速记录**：经历/输入、判断/决策、行动/结果、复盘/更新四个入口。

首页顶部固定一句：

> AI不替你思考，而是帮你运营自己：判断、决策、行动、改变。

## 四类记录模板

### 经历与输入

```text
发生了什么 / 来源是什么 / 为什么与我有关 / 先不急着做什么
```

### 判断与决策

```text
已确认事实 / 我的假设 / 我的判断 / 当前决定 / 以后何时重看
```

### 行动与结果

```text
准备做什么 / 实际做了什么 / 结果是什么 / 证据在哪里 / 下一步
```

### 复盘与变化

```text
什么发生了变化 / 什么没有变化 / 原因 / 应更新哪条当前认识
```

YAML只保留AI和首页真正需要的字段：

```yaml
type: input | judgment | decision | action | result | review
status: active | done | paused | historical
created: YYYY-MM-DD
updated: YYYY-MM-DD
effective_from: YYYY-MM-DD
source:
privacy: private
```

普通用户不需要手工维护全部字段。

## AI协作底线

1. 用户最新明确表达高于旧笔记。
2. 示例、测试角色和AI推测不得写成用户身份。
3. 身份、经历、资产、健康、家庭和当前目标改变前，必须让用户确认。
4. 过去真实经历与当前状态分开保存，不用覆盖历史来“保持最新”。
5. 用户说“记录/写入/更新”时，可在白名单目录写普通记录；改变当前底稿时先展示变化摘要。
6. 禁止修改`.obsidian`、`.claudian`、`.claude`、`90_系统设置_不用先看`、启动文件和脚本。
7. 禁止批量删除、移动和改名；所有正式包默认空白，不含虚构用户数据。

`AGENTS.md`与`CLAUDE.md`不各写一套规则，只做薄入口，共同指向`80_AI助手/AI协作与写回规则.md`。

## AI与插件边界

### 首版只保留

- Obsidian：本地Markdown载体。
- Homepage：启动后打开首页。
- Dataview：汇总最近记录和状态。
- Claudian：可选AI交互界面。
- Claude Code + DeepSeek：首版候选默认AI运行时，但不作为第一次打开的前置条件。

### 首版不加入

- Templater、QuickAdd、Tasks等更多插件。
- 多Agent、自动同步、自动发布、网页账号系统。
- 健身、英语、内容创作等具体场景追踪看板。
- 六维能力模型、双驾驶舱、CRM、财务、复杂资产账户。
- 根库当前的完整时间治理和80多个目录逻辑。

## 从旧资产复用什么

| 旧资产 | 复用 | 不复用 |
|---|---|---|
| 个人降噪启动包 | 输入→判断→行动→结果、AI写回白名单、无AI可用、首页入口 | “噪音”覆盖全部成长、API第一步、固定7天、情绪/健康/专注大杂烩 |
| 个人能力复利驾驶舱 | 空白母版与运行副本隔离、证据优先、发布前清凭证、确认边界 | 六维技能、双驾驶舱、复杂批次引擎和大量职业示例 |
| Z总Personal OS | 当前事实与历史分开、来源意识、身份事实门禁 | 完整治理层、复杂索引、多Agent和个人专属目录 |
| 场景网页看板 | 未来作为具体成长主题的增强插件 | 不塞进免费基础知识库首页，不把免费层变成看板简版 |

## 首版验收

### 无AI路径

- 新用户十分钟内完成《我的当前成长底稿》。
- 能新增一条经历、一条判断、一条行动结果。
- 首页能看到最近记录，关闭重开后仍存在。

### AI路径

- 安装与配置不超过15分钟，否则记录卡点。
- AI只读必要的5—8个入口文件，不全库扫描。
- AI能从底稿追问缺口，但不得创造身份、经历或资源。
- 用户明确要求后，能把一条内容写入正确目录。
- 修改当前底稿前准确复述“旧值→新值”。

### 发布净包

- 不含API Key、登录态、AI会话、真实用户数据和绝对路径。
- 插件许可证和版本来源完整。
- 空白包、测试副本和用户运行副本严格分开。

## 最小开工顺序

```text
1. 复制旧个人降噪包的最小插件与视觉壳，不复制用户内容
2. 按本规格重建00—60目录与四类模板
3. 建首页和《我的当前成长底稿》
4. 写一份核心AI协作规则，并生成AGENTS/CLAUDE薄入口
5. 用合成用户跑无AI路径
6. 再接Claude Code + DeepSeek跑AI路径
7. 录屏或直播展示，收集真实卡点
```

首版完成的定义不是“文件很多”，而是：

> 一个陌生人能在十分钟内建立第一份属于自己的成长底稿，并知道下一次回来该记录、判断、行动还是复盘。
