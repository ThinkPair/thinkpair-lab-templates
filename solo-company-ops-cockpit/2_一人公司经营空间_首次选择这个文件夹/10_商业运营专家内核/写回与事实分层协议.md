# 写回与事实分层协议

## 权限模式

AI 运行权限采用 `normal + acceptEdits`。用户直接说“保存、写入、更新、记录、填进去、执行”或同等动作，就是对本轮明确内容和白名单目标的授权；校验通过后直接执行，不再二次确认。AI 主动提议写入时才需一次短预览与确认。不得通过改成 `yolo` 解决确认摩擦；`yolo` 不会绕过项目守卫。

## 四类信息必须分开

1. **用户事实**：用户明确陈述，或由其经营材料直接证明的事件、对象与数字。
2. **外部证据**：可核验的外部来源、日期和结论，只能支持研究判断，不能自动成为用户经营事实。
3. **待验证假设**：尚未由真实回复、行为、报价或到账验证的设想。
4. **AI 建议**：AI 基于事实提出的动作或判断，不是已经发生的事实。

项目文件只接收通过事实门的用户事实。能力商品化文件可以保存待验证假设；外部证据应写入对应验证记录并带来源与日期；AI 建议在用户确认前只能停留在对话中。真实核账中的输入是用户在专用计算页确认的经营事实，创业预估中的输入始终是待验证假设；两者不得混用。

## 写回白名单

确认后，AI 只可新增或编辑：

- `20_经营数据/当前项目/*.md`
- `20_经营数据/经营状态.md`
- `30_五维周复盘/历史周复盘/*.md`，但不得覆盖其他周文件
- `40_能力商品化/验证记录/*.md`
- `20_经营数据/经营核算/AI结论/*.md`，仅允许新增 `record_type: finance_ai_insight`
- `20_经营数据/经营目标/行动计划/*.md`，仅允许新增经确定性复算的 `record_type: operating_action_plan`
- `60_AI商业运营专家/已确认写回记录.md`

README、模板和历史周复盘目录中的说明文件不属于日常写回目标。

两类文件只能通过固定脚本新增，不能由通用 Write/Edit 直接创建：`finance-entry.js` 可向 `60_AI商业运营专家/核算草稿/*.md` 独占写入一份仅含输入的临时草稿；`session-export.js` 可向 `60_AI商业运营专家/对话归档/*.md` 独占写入一份真实来源、已脱敏的会话证据。用户直接要求代填或导出时，脚本完成自身校验后直接新增；AI 主动提议时才交给一次原生确认。两者均不得覆盖已有文件。

AI 不得新建、编辑或覆盖 `20_经营数据/经营核算/实际核算`、`创业预估`、`产品收费方案` 或 `20_经营数据/经营目标/目标方案` 中的任何记录。`AI结论` 与 `经营目标/行动计划` 都只允许新增，不允许用 Edit 改旧记录；上游哈希变化后应创建绑定新哈希的新记录并让旧记录自然失效。

## 单一事实源与派生镜像

- 项目事实源是 `20_经营数据/当前项目/*.md`。
- 周复盘事实源是 `30_五维周复盘/历史周复盘/*.md`；`20_经营数据/经营状态.md` 只派生当前周次和全局唯一经营动作。
- 能力商品化事实源是 `40_能力商品化/验证记录/*.md`；`能力商品化起点.md` 只作只读说明。
- 经营核算事实源是专用计算页确认生成的 `20_经营数据/经营核算/实际核算/*.md` 与 `创业预估/*.md`；产品收费方案快照位于 `产品收费方案/*.md`。
- AI 对核算的解释只保存在 `AI结论/*.md`。它是建议层，不是公式结果；只有 `calculation_id + input_hash` 与当前核算完全一致时才可参与首页。
- 盈利目标事实源是目标页确认生成的 `经营目标/目标方案/*.md`；AI 永久只读。行动拆解保存在 `经营目标/行动计划/*.md`；只有 `target_plan_id + target_input_hash + breakdown_input_hash` 可复算且仍指向当前目标时才可参与首页。

首页只读取这些事实源和派生镜像，是只读展示层。AI 必须通过白名单 Markdown 更新看板，不得修改首页代码、查询或样式来模拟写入，也不得要求用户在首页另行维护第二套数据。

五维周复盘写回必须在同一授权轮次中同时处理周文件和经营状态镜像。发生部分失败时不得回滚或覆盖已写周文件；应以周文件为准，报告镜像未同步并在下一次用户授权时修复。

## 创业算账的唯一直接保存例外

`00_开始这里/创业算账.md` 是本产品唯一允许用户直接填写并保存正式经营核算的专用工具。计算页中的“保存本次结果 → 查看摘要 → 确认保存”构成用户对本地确定性计算器的单次授权，由计算页生成新的核算与收费方案记录。

用户也可让 AI 通过 `/finance-entry` 逐项确认并暂存一份核算输入草稿。该桥只接受 `quick_v3` 用户输入，拒绝结果、输出路径、ID、哈希、版本和未知字段；草稿写入 `60_AI商业运营专家/核算草稿`，必须 `privacy: sensitive + retrieval: excluded`，不参与首页或目标倒推。它不替用户确认正式核算：计算页载入后仍须用户检查并点击确认保存。

AI 可以帮助用户理解字段、追问缺失事实和解释已保存结果，但必须遵守：

- 不替用户点击确认保存，不把聊天内容直接写成核算记录。
- 不手工重算、修正或覆盖 `sustainable_profit`、`cash_net_change`、`safety_value` 等公式结果。
- 不把创业预估升级为真实核账，不把未知值补成 `0`。
- 用户要求保存 AI 解读时，只能按本协议向 `AI结论` 新增一条绑定当前 `calculation_id + input_hash` 的建议记录。

## 永久禁止区

- `10_商业运营专家内核/**`
- `.claude/**`
- `.obsidian/**`
- 插件、主题、CSS、首页代码、运行时和系统设置
- `20_经营数据/经营核算/实际核算/**`、`创业预估/**`、`产品收费方案/**`（对 AI 永久只读）
- `20_经营数据/经营目标/目标方案/**`（对 AI 永久只读）
- 白名单之外的任何文件

禁止删除、移动、覆盖原文件、批量重命名或批量改写。归档与重开通过项目文件的 `record_status` 完成，不移动文件。

## 从访谈到写回

AI 先主动访谈，并把自然语言整理成“【看板草稿】”。看板草稿用于让用户检查事实、假设和建议；若用户同时直接要求保存或更新，该指令已经构成本轮授权。

当草稿包含 AI 建议时，必须让用户采用、修改或放弃。若用户已明确采用并要求保存，直接校验和写入，不得再重复询问或展示二次预览。若用户只采用了建议，但没有表达写入意图，AI 可展示一次短预览。将建议写成项目“下一步”、项目“本周复盘”、`maximum_bottleneck` 或 `unique_operating_action`，都属于经营决定，但同一决定不得被拆成多次重复确认。

用户只需在对话中回答与确认，不能被要求填写首页、模板或 YAML。AI 负责按 schema 生成精确拟写内容。用户需要核算时可以直接使用创业算账页；这一例外不允许 AI 把其他经营流程改回用户手工填表。

## 写回决策

用户直接下达保存、写入、更新、记录、填进去或执行指令时，AI 校验以下内容后直接执行：

- 目标文件完整相对路径。
- 新增或修改的字段与前后值。
- 每项内容属于事实、外部证据、假设还是建议。
- 金额校验、事实门校验及可能的异常提醒。
- 写回后将形成的唯一下一步或唯一经营动作。

若目标是 `经营核算/AI结论`，实际记录必须包含来源核算路径、`calculation_id`、`input_hash`、核算模式、`maximum_issue` 与 `unique_action`。守卫在写入当下检查来源仍存在、期间资格有效且 ID 与业务哈希未变化；不匹配时返回“来源需要复核”，不得保存过期结论。需要短预览时只展示来源期间、最大问题和唯一动作。

若目标是 `经营目标/行动计划`，实际记录必须保留来源目标路径、`target_plan_id`、`target_input_hash`、`breakdown_input_hash`、转化依据、显式冲刺系数、`unique_action` 和确定性脚本产生的完整 JSON 数据块。守卫在写入当下复算来源核算与目标；不得手改脚本输出，也不得保存绑定旧目标的行动。需要短预览时只展示目标月份、关键差额、最大断点和唯一动作。

只有 AI 主动提议写入且用户尚未表达写入意图时，才展示一次短预览。短预览以“【写回预览】”开头，只列完整相对路径、关键字段变化、是否出库和能否撤销，不展示内部授权数据、脚本命令或整份 Markdown。用户确认后立即执行，不再确认文件名或建议。

## 授权语义

用户的直接动作指令即为授权，无需先出现固定格式的预览。有效示例包括：`保存这条结论`、`把它写入看板`、`更新这个项目`、`记录这次复盘`、`填进去`、`执行吧`。AI 主动展示短预览后，`确认`、`可以写`、`就按这个` 等也构成授权。不得要求用户复述固定口令。

只说“好”“行”“知道了”等语义不足时，不得拒绝或要求用户再输入口令；应把实际写回请求交给一次原生确认。否定、暂停或取消立即停止。附带修改条件时，如“可以写，但先把价格改一下”，先纳入修改并更新拟写内容，再发起一次原生确认。

授权只覆盖本轮用户明确指向的文件与字段，不可扩大范围；敏感、批量、越权、删除、移动或重命名操作不因普通写入指令而放行。

守卫对库内读取与精确匹配的确定性预演自动放行；明确公开外查构成本任务授权。外部目录读取先交给原生确认；用户直接要求的普通白名单写、核算草稿和真实会话导出直接执行；AI 主动提议时由原生 `ask` 补足一次确认；发送、发布、上传、表单、外部覆盖、移动与重命名逐次返回原生 `ask`。命令不得串接、重定向、替换或嵌套解释器；`enableBangBash` 不构成授权。密钥、守卫/内核修改、提权、永久或递归删除、支付、刚下载程序执行与系统安全设置永久拒绝。AI 不得读取或修改 `.claude/settings.json`、`.claude/hooks/**`、权限设置与运行审计，不得将其作为失败后的自调试材料。

写回失败后最多重试一次，且仅限错误已明确指出可修正的 schema 或路径问题。来源失效、业务资格不符或永久禁止时不得重试，应直接说明原因和可执行下一步。

## 写回后核验

1. 只修改本轮获授权的白名单文件与字段。
2. 重新读取目标文件，检查 YAML、金额精度、唯一下一步和事实层级。
3. 向 `已确认写回记录.md` 追加时间、目标文件、字段摘要、实际确认语和核验结果；记录确认语不代表扩大授权。
4. 用“【已写入看板】”复述重新读取到的项目六字段、能力验证或周复盘关键值，并重新计算适用的经营数字。
   对核算解读不得重新计算公式数字；应复述来源核算文件中已经保存的结果，并核对新结论的 `calculation_id + input_hash` 仍与来源一致。
   对目标行动计划必须调用同一确定性脚本复算，核对 `target_plan_id + target_input_hash + breakdown_input_hash`、全部结果数字与唯一动作；不得由 AI 口头声明通过。
5. 向用户报告实际完成项；失败或部分写入必须如实说明，不得假称成功。
6. 基于复读后的看板只提出一个后续建议，并明确它仍是建议；用户决定采纳并要写入时，将该指令视为新一轮授权并直接执行，不重复确认。

## 外部研究

只有用户明确要求“搜索、查资料、对标、验证市场”等外查行为时才进行。记录至少包含来源、访问日期、可核验结论和局限。外部行业数据不能证明某个客户已回复、某笔报价已提出或某笔款已到账。

Chrome 控制默认关闭。公开网页研究使用普通联网工具，不要求用户开启 Chrome；确需操作登录态网页时，第一次先说明动作和影响，用户开启后每次改变外部状态仍需原生确认。

用户明确要求保存 AI 对话时，必须用 `/session-export` 从 `.claudian` 元数据关联用户目录下的真实 Claude transcript；不得依靠当前上下文回忆拟写。导出只保留用户与助手文字，标记完整性口径，自动遮蔽疑似密钥，并保存到 `60_AI商业运营专家/对话归档`，默认不参与检索。
