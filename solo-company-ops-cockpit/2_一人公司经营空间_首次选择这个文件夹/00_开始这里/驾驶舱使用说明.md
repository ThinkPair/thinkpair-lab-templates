# 驾驶舱使用说明

首页是固定在 Obsidian 界面中的只读经营看板。它不是给懂商业的人看的财务后台，而是帮助有一技之长的创业者依次看懂：**有没有赚到钱、钱为什么还没进来、下一步只做什么**。首页不承担数据录入：项目和复盘经由右侧“商业运营专家”进入；需要算账时，点击首页的“创业算账”打开独立工具。

## 先做一次创业算账

“创业算账”是首页看板里的一个独立功能，不是整张看板。点击后，它会在新标签中打开 `00_开始这里/创业算账.md`；固定首页保持不动，关闭计算页即可回到看板。

### 1. 选择核算口径

- **已经经营**：选择“真实核账”，默认使用最近一个完整经营周期。
- **尚未开始**：选择“创业预估”，默认使用当前自然月作为计划周期。

创业预估永远会标注为预估，不会进入真实经营业绩。保守、基准和乐观三档由固定公式自动生成，不要求用户手填三遍。

### 2. 先填最少的核心数字

- **真实核账 8 项**：完成工作对应的收入、经营现金流入、经营现金流出、直接履约成本、固定经营成本、自己的合理工资、可动用现金、完成剩余承诺所需成本。完成数量是可选项，只用于追加每单能留下多少钱和保本数量。
- **创业预估 6 项**：单位售价、单位直接成本、固定经营成本、自己的合理工资、现实预计完成量、最大稳定交付量。启动后剩余现金与一次性启动投入是可选项。
- 产品／服务名称和计价单位可直接填写；“一单、一次、一个项目、一位客户、一个月”可快捷选择，也可自定义。

计算页先解决“现在赚不赚钱、保本要做到多少、现有能力能不能承接”。复杂交付模型、共同成本分摊和公式说明不会铺满首屏；需要时再查看折叠说明。

### 3. 填写真实数字

- 收款、已交付确认收入、利润和现金是不同数字。
- 老板合理工资计入可持续利润成本；老板实际取款才会减少现金。
- 公司共同成本只在公司层扣除一次，不按产品重复扣除。
- 不知道的数保持空白，不用 `0` 补齐。只有你确认该项真的为零时，才填 `0`。

数据不足时，计算页显示“暂时无法判断”和最少待补项，不生成健康评级。数据齐全后，本地固定公式给出可持续利润、经营现金净变化、交付安全／启动资金缺口、单位贡献和保本与产能提醒。

### 4. 确认保存并回流首页

1. 点击“保存本次结果”。
2. 检查核算口径、周期、利润、现金和安全／缺口摘要。
3. 点击“确认保存”，系统新建一份本地 Markdown 核算快照并复读验证。

历史核算不会被覆盖。载入旧核算后再修改，会保存为新快照。未点击确认保存的输入只是本机临时草稿，不进入首页和经营事实层。

首页只显示最新有效的算账结论：核算口径、真正赚／亏、现金净变化、完成承诺后还剩／还缺，以及与该次核算精确绑定的经营解读。输入变化后，旧解读会自动失效。

### 5. 制定本月盈利目标

核算保存后，同一页面自动出现“制定本月盈利目标”：

1. 选择目标月份。
2. 填写支付全部成本和自己的合理工资后，公司希望真正赚到的月利润。
3. 需要时填写希望经营现金增加多少；默认先保证现金不减少。
4. 只有原核算没有提供时，才补充平均每笔成交本月实际能收到的钱、每个交付单位可确认的收入或每月最大稳定交付量。
5. 查看摘要并点击一次“确认生成目标”。

固定公式会同时给出两条线：

- **利润交付线**：保本营业额、盈利营业额、目标交付量和产能状态。
- **销售收款线**：最低实收目标；平均每单实收已知时，再生成月成交目标。

销售、实收、确认收入和交付量是四个不同数字。单位贡献不为正时先处理定价或成本；目标超过稳定产能时先调整价格、成本、交付方式或产能，不继续扩大获客。

保存目标后，首页只增加一张紧凑目标卡，显示当月目标、当前差额、产能状态和一个“本周先做”。核算或目标发生变化时，旧目标与旧行动自动退出当前首页，但历史文件不会被覆盖或删除。

### 6. 经营助手负责拆成行动

- “不会填？让经营助手逐项确认”会把当前待补项和已有输入带到侧栏。
- `/finance-review` 只解释已确认保存且未变更的核算。
- `/target-breakdown` 读取当前有效目标，每轮只问 1—3 个问题，确认当前实收、成交、确认收入、交付、剩余经营日和转化依据，再由固定脚本生成剩余差额、漏斗与每日任务。
- 没有历史转化率时，优先记录用户确认的粗略假设；完全不知道时进入七天校准，只记录触达、回应、讨论、报价和成交，不制造行业默认目标。
- AI 可以解释和组织行动，但不能改写公式、输入哈希、目标数字或派生数字。
- 没有配置 AI 时，仍能独立填写、计算、保存和查看历史核算。

## 第一屏怎么读

### 1. 先看“本期经营结果”

- **没有实际回款**：尚未赚到钱。
- **已有实际回款，但没有结构化成本数据**：有现金进账，利润未知。
- **报价不等于收入**；价格设想、内部试卖价和待验证方案中的价格假设都不算报价。

### 2. 再看六步赚钱路径

```text
待验证方案 → 真实回应 → 具体讨论 → 真实报价 → 实际到账 → 复购证据
```

这是从“一技之长”走到“可持续生意”的最短可观察链路。首页会直接指出当前卡在哪一步。`planned` 且没有通过事实门的记录只叫“待验证方案”；有人回应并开始讨论具体工作后，才进入真实项目。

### 3. 再看三个经营区

- **找到客户**：有没有方案、真实回应和具体讨论。
- **成交收钱**：有没有真实报价、客户已经接受的明确应收和实际到账。
- **交付复购**：有没有结清、复盘和复购／转介绍证据。

### 4. 最后只看一个动作

第一屏把多个问题收敛为“当前卡点”和“现在只做这一件事”。它不是删除其他工作，而是让本周期只有一个全局经营动作，避免同时开很多坑。

## 第二层保留完整经营逻辑

第一屏负责判断，向下滚动才进入明细：

- **六字段**：客户、项目、报价、回款、下一步、本周复盘。
- **四列项目明细**：待澄清、进行中、等待收款、待复盘。只有形成明确应收后才进入等待收款。
- **五维经营体检**：营收闭环、成本效率、组织流程、风险合规、数据迭代。

这些能力仍完整存在，只是不再挤占第一屏。AI 诊断时仍使用五维和六字段，用户需要追溯时再看第二层。

## 一条完整工作链

```text
AI 读取当前看板
→ 自动判断真实项目或能力商品化路径
→ 每轮主动问 1—3 个高价值问题
→ 生成看板草稿并给出一条建议
→ 用户采用、修改或放弃
→ AI 只展示一次目标位置、关键变化、是否出库和可撤销性
→ 用户用自然语言明确同意
→ AI 立即执行获准操作、复读并核验
→ 首页自动刷新
```

回答问题、采用建议和授权写入是不同的事。你直接说“保存、写入、更新、记录、创建、填进去”等动作时，这句话本身就是对本轮合法库内白名单写回的授权，不再要求二次确认。只有 AI 主动提出要把内容落库时才展示一次短预览；你只说“好/行/知道了”等语义不足时，由原生窗口确认一次。否定时立即停止，附带修改条件时先更新内容再确认一次。

十个命令只用于新会话快速进入工作流。访谈开始后始终用自然语言继续，AI 会自动判断继续追问、直接执行已授权写回，还是在主动提议修改时展示一次短预览，不会要求你重复输入命令。

## 金额与事实门

- 仅发出消息但没有回应，不算真实客户或项目。
- 对方回应并开始讨论具体工作后，才能建立项目。
- 报价只有真实向对方提出后才能填写。
- 回款只记录累计实际到账；未知金额保持为空，不用 0 冒充。
- 报价不等于客户已经接受的应收。明确待收必须有合同、客户确认或付款安排证据；证据不足时保持未知，不用“报价－回款”机械推导。
- 项目六字段没有结构化成本，因此只看“有回款”仍只能证明现金进账。确认保存一次完整的创业算账后，首页才会显示该次核算的可持续利润。

## 十个 AI 入口

| 入口 | 命令 | 什么时候用 |
| --- | --- | --- |
| 经营启动 | `/ops-start` | 新对话先接手看板、判断路径 |
| 项目更新 | `/project-update` | 新增真实项目或推进现有项目 |
| 五维复盘 | `/weekly-review` | 完成本周五维事实、断点与唯一动作 |
| 能力商品化 | `/monetization` | 还没有真实项目时，把能力推进到可验证动作 |
| 经营诊断 | `/ops-diagnose` | 基于已有数据定位当前最大经营断点 |
| 经营收口 | `/ops-close` | 一轮工作结束时集中整理事实、授权写入和复读 |
| 核算解读 | `/finance-review` | 只读已保存核算，形成一个最大问题和一个立即动作 |
| 目标拆解 | `/target-breakdown` | 读取当前有效目标，确定性生成差额、漏斗、每日任务和本周唯一动作 |
| 核算代填 | `/finance-entry` | 把访谈中确认的输入整理成计算页待检查草稿 |
| 会话导出 | `/session-export` | 从 Claudian 原始会话导出脱敏存档 |

AI 和首页读取同一批 Markdown。AI 建议必须与事实分开；未经用户敲定，不能反向写成经营事实。用户的直接写入指令就是本轮授权；AI 主动提议时才需要一次短预览或原生确认。AI 只能写经营数据白名单，不能修改首页、CSS、插件、专家内核或系统设置。

十个命令只用于新会话快速进入相应工作流，进入访谈后始终用自然语言继续。Claudian 权限保持 `normal + Safe`（配置字段为 `acceptEdits`），不使用 YOLO。库内读取、分析和公式预演自动进行；用户直接要求的合法库内写回直接执行，AI 主动提议时确认一次；公开网页研究按用户明确任务授权；发送、发布、上传、表单、外部覆盖、移动和重命名由原生窗口逐次确认。

## 隐私与分享

使用后的本机经营空间可能包含项目、复盘、创业算账快照、盈利目标、行动计划、进度与转化假设、能力验证、市场反馈、AI 解读、临时草稿、会话和模型凭证，不能直接压缩或分享。可分享的发布净包必须由脱敏构建生成，且发布校验必须确认用户经营数据、AI 会话和真实凭证均为零残留。具体文件数以当次校验输出为准。
