# 核算代填｜只把用户输入送到计算页

先读取 `10_商业运营专家内核/AI接手索引.md`、`诊断追问与验收协议.md` 和 `写回与事实分层协议.md`。本命令只能生成临时核算输入草稿，不能创建正式核算、修改公式或替用户点击计算页的“确认保存”。

按顺序执行：

1. 先判断真实核账或创业预估，每轮只问 1—2 个普通人能回答的问题。未知保持 `null`，不得补成 `0`。
2. 把摊销、折旧、押金、贷款等项目分别问清“是否在本期真实付钱”；未真实付款不得混入现金流出。收款与确认收入的差额只称“待核对时间差”，不得自动说成预收款。
3. 只整理 `quick_v3` 用户输入。禁止提供或接受结果、输出路径、记录 ID、哈希、计算版本和未知字段。
4. 将完整输入 JSON 做 UTF-8 base64url 编码，只调用以下固定形式的只读预演：

```text
node .claude/skills/commercial-operations-expert/scripts/finance-entry.js --preview --input-base64 <base64url>
```

5. 若脚本报告缺失或错误，继续追问，不自行修补。若 ready，向用户展示：核算期间、拟填字段、确定性结果摘要、异常提醒，以及计算页仍需用户确认保存。用户不需处理任何脚本参数。
6. 用户已直接要求“帮我填入、保存草稿、写进计算页”时，该指令即为草稿写入授权，不再展示写回预览或要求二次确认。只调用：

```text
node .claude/skills/commercial-operations-expert/scripts/finance-entry.js --stage --input-base64 <与预演完全相同>
```

7. 若 AI 主动建议代填但用户尚未表达写入意图，展示一次只包含“拟填字段、草稿位置、尚不是正式核算”的短预览；语义不足时将上述 `--stage` 操作交给原生确认一次。
8. 写后复读脚本返回的固定目标，明确说明“只已填入草稿，尚未形成正式核算”。引导用户打开创业算账页检查输入并点击一次“确认保存”。
