# 自媒体运营看板 Obsidian 设计合同 v1

## Design target

- Product: 一人公司商业运营专家驾驶舱 · A 型降噪实验室自媒体运营模板
- Screen: Obsidian 固定首页“转化漏斗”
- Surface and viewport: Windows Obsidian 桌面阅读视图；目标内容区 1180–1440px 宽，参考整窗 1440 × 1024
- Intended user: 每周复盘抖音、小红书及后续渠道内容经营结果的个人创作者与一人公司负责人
- 30-second outcome: 30 秒内确认已取得的触达、有效线索、付费与实收，识别平台来源、近四周变化及数据缺口；未知不得被误读为零
- Primary action: 打开“补录数据”，通过截图／CSV／少量手填进入用户确认后的 Markdown 事实记录
- Supporting actions: 切换 4/12 周、筛选平台、查看阶段明细、进入内容归因和数据明细、刷新 Dataview

## Information hierarchy

- Visual hero: 左侧约 64% 的六阶段分段漏斗；有真实阶段时突出当前阶段，无数据阶段显示虚线“待补录”
- First eye-line: 触达、有效线索、首次付费、实收四个结果及“实际／演示／待补”状态
- Second eye-line: 漏斗英雄区和平台筛选
- Third eye-line: 有效线索来源、近 4/12 周趋势、数据证据完整度
- Deliberately de-emphasized: 文件路径、插件、字段名、跨平台未去重声明、来源详情和更新时间
- Off-screen or later routes: 内容归因、全部事实记录、原始截图／CSV、用户主动复盘和 AI 分析

## Visual tokens

- Grid and margins: 内容区 12 列；外边距 24px；主区 8 列＋右栏 4 列；间距 16px；Obsidian 左右侧栏默认折叠
- Spacing scale: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px
- Chinese type family and weights: `"PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`；300/400/500/600
- Numeric type family and weights: `"Segoe UI Variable Display", "Inter", "Segoe UI", sans-serif`；300/400/500/600，tabular-nums
- Type scale: 42/48 结果数字；30/38 页面标题；26/32 图表总数；18/26 模块标题；14/22 正文；12/18 元信息；10/15 图表辅助标签
- Canvas color: `#F4F2F8` 暖灰紫，叠加克制的径向柔雾
- Surface colors: 主表面 `rgba(255,255,255,.82)`；支持表面 `rgba(255,255,255,.66)`；强调表面 `rgba(238,233,255,.88)`
- Primary accent: ultraviolet `#6D4CFF`，用于选中态、英雄漏斗焦点和关键趋势
- Data category colors: 抖音 `#6D4CFF`；小红书 `#EC8795`；B站 `#55B9BC`；均降低明度或透明度后使用
- State colors: confirmed `#2F746A`＋实心圆；estimated `#9A6B25`＋半实心圆；unknown `#70727A`＋空心圆；conflict `#B8485D`＋菱形；missing `#9B9DA6`＋虚线
- Radius: 英雄面 26px；支持面 20px；按钮 11px；胶囊 999px
- Border: `1px solid rgba(50,45,72,.09)`；选中态 `rgba(109,76,255,.28)`
- Shadow, blur, and texture: 英雄 `0 22px 70px rgba(49,39,82,.09)`；支持面 `0 8px 28px rgba(49,39,82,.06)`；只在支持时使用 16px blur
- Icon family and stroke: Obsidian 内置 Lucide；regular 16–20px；不嵌入自制图标
- Memorable brand move: 漏斗“有效线索”左缘的酸性黄绿 `#C8FF45` 焦点刻度；只用于当前焦点和待补提醒

## Chart system

- Hero chart and purpose: 六阶段 stage rails，回答“从内容到付费，当前已有哪层事实、哪层仍缺数据”；混合单位，不宣称同一人群 cohort
- Supporting chart 1 and purpose: 三平台有效线索来源环图；没有已确认线索时显示中性空环和“待补”，不生成伪占比
- Supporting chart 2 and purpose: 近 4/12 周有效线索折线；没有事件时保留网格和空状态，不把缺失点绘制为零
- Stroke and marker language: 主趋势 2.5px＋6px 实心圆；次趋势 1.5px＋4px 圆；漏斗焦点段 1px 内高光
- Grid and axis language: 3 条 `rgba(57,51,75,.08)` 水平网格；隐藏 y 轴轴线；x 轴 10px 灰紫；数据存在时从零基线开始
- Label and annotation language: 漏斗左侧阶段与单位类型、轨道内平台值、右侧总数＋单位；未知使用“待补录”文字
- Hover and selection: 阶段、平台、时间范围和视图标签均可点击；阶段打开本地明细抽屉；按钮使用 Obsidian 内置图标
- Empty and missing states: 真实 0 显示 0；missing/unknown 显示虚线空轨或空环；conflict 明确标红并进入数据明细

## Data semantics

- Event units: 内容触达为平台事件次数，显示“次”；同一内容的最新快照按字段取最近已知值
- Person units: 新增关注、有效线索、深度沟通按平台记录近似为“人”；跨平台身份不去重
- Order units: 首次付费与升级续费按已确认订单事件，显示“单”
- Revenue units: 已到账人民币，显示“¥”；意向金额、报价和未支付订单不计入实收
- Conversion denominators: 只在分子与分母均已确认且语义可比时显示；当前首页默认不显示跨单位精确转化率
- Cross-source deduplication rule: 首版不跨平台去重；同一内容同一平台的多个快照按 `content_id + platform` 合并为最新字段视图，历史记录不覆盖
- Evidence states: confirmed / estimated / unknown / conflict / missing，使用文字＋形状，不能只靠颜色
- Demo-data label: 空白母版显示“待补录”；运行副本显示“实际快照”；fixture 只能在显式演示模式显示“演示数据”

## Interaction

- Default time range: 近 4 周
- Filters: 近 4 周／近 12 周；全部／抖音／小红书／B站；转化漏斗／内容归因／数据明细
- Primary interaction flow: 点击“补录数据”→提供截图／CSV／少量事实→AI 或模板生成待确认内容→用户确认→新增 Markdown 快照／事件→返回首页刷新
- Drill-down target: 漏斗阶段本地抽屉；内容归因与数据明细在同一固定首页切换，不打开外部网页
- Keyboard and focus expectations: 所有按钮可 Tab 到达；`:focus-visible` 2px 紫色外环；Esc 关闭抽屉；按钮具备可访问名称
- Responsive fallback: 1024–1199px 右栏下移；小于 800px 单列，结果两列，漏斗压缩为横向阶段轨道

## Working UI versus sales image

- Working UI priorities: 读取真实 Markdown、口径可信、未知不伪装成零、长时间使用舒适、补录与追溯明确
- Sales image priorities: 仅使用通过验收的 Obsidian 工作界面截图，强调本地、可追溯和三平台复盘
- Elements allowed only in sales image: 产品卖点标注、设备框、价格、CTA、舞台背景、配色与字体样本

## Implementation

- Existing runtime or template: v0.1.4 Obsidian 空白根母版；DataviewJS 作为只读聚合层，business-cockpit.css 作为共用样式层
- Chart implementation: 漏斗用语义化 DOM/CSS stage rails；环图与趋势用 DataviewJS Canvas；图标使用 Obsidian setIcon
- Token implementation: `business-cockpit.css` 中 `--sm-*` CSS 变量；页面只引用共享 token
- Fonts and asset sources: 系统中文字体＋Segoe UI 数字；Obsidian 内置 Lucide；不引入第三方 Logo 或远程字体
- Realistic data source: 空白母版不载入真实数据；独立降噪实验室运行副本读取三期 Markdown 快照，来源指向当前统一台账和平台截图

## QA acceptance

- Primary reference viewport: Windows Obsidian 1440 × 1024；阅读视图；左右侧栏折叠；与目标图按同一裁切比较
- Thumbnail test: 25% 缩略时四个结果和左侧漏斗是第一眼，右侧两个支持图明显退后
- Long-label test: 28 汉字内容标题在归因表中两行省略且 hover 可见；平台和阶段标签不碰撞
- Zero, missing, and extreme-value test: 0 订单、全线索缺失、单平台 95% 占比、100,000+ 触达均不破版；未知不当 0
- Reference-comparison passes: 至少一轮宏观构图／氛围对比，一轮微观字体／对齐／圆角／图表细节对比；实现截图与目标图同屏检查
- Accessibility checks possible from implementation: 键盘焦点、按钮名称、对比度、125% 缩放、Esc 关闭抽屉、颜色之外的状态文字
