# 降噪实验室｜一人公司商业运营专家驾驶舱 v0.1.2 根产品母版

> [!important] 这是唯一产品源
> 本目录只用于迭代产品结构、界面、公式、专家内核和发布文件。测试、录屏和真实经营前，先手工复制整个目录并在副本中操作。禁止在本母版中填写经营数据、配置真实密钥、产生 AI 会话或把测试副本内容合并回来。

本产品把商业运营做成一套本地经营空间：首页呈现经营结论，“创业算账”独立页用固定公式完成核算与盈利目标倒推，AI 主持项目访谈、目标拆解和复盘，所有已确认事实保存为本地 Markdown。

## 产品结构

```text
Obsidian 操作界面
→ 本地 Markdown 经营数据
→ 确定性创业算账引擎
→ 盈利目标与运营任务确定性倒推
→ 商业运营专家知识内核
→ Claudian 读取、诊断、追问
→ 用户确认后写回
```

启动后会直接打开并固定首页。首页是只读经营看板，第一屏只回答三个非商业创业者最需要看懂的问题：**现在赚不赚钱、问题出在哪里、接下来先做什么**。

首页按从结论到行动的顺序呈现：

1. **本期经营结果**：真正赚／亏、现金变化、履约资金和保本线。
2. **本周先做**：只保留一个可验收动作。
3. **六步赚钱路径**：产品验证 → 真实回应 → 具体讨论 → 正式报价 → 实际到账 → 复购／转介绍。
4. **项目与经营体检**：继续追踪当前项目和五个经营维度。

六字段、四列项目明细和五维经营体检没有删除，而是放到第二层供追溯和诊断。用户不在首页填表：项目和复盘信息通过右侧“商业运营专家”录入；“创业算账”是独立的直接填报工具。

## 创业算账

首页顶部的 **“创业算账”** 按钮会在新标签中打开独立计算页，固定首页不会被替换。

1. **已经开始经营**：只先回答 8 个核心数字——已完成工作对应的收入、经营现金流入、经营现金流出、直接履约成本、固定经营成本、老板合理工资、可动用现金和剩余履约成本。完成数量是可选项；填写后才追加单位贡献和保本数量。
2. **尚未开始经营**：只先回答 6 个核心数字——单位售价、单位直接成本、固定经营成本、老板合理工资、现实预计完成量和最大稳定交付能力。启动后剩余现金与一次性启动投入放在可选区，不阻塞第一次判断。
3. 利润、现金、交付安全、每单能留下的钱、保本量和产能可行性都由固定公式计算；界面不要求用户先理解多产品分摊、四种交付模型明细、费率或三档情景公式。
4. 每项结论有独立的数据就绪状态：数据够算利润时先显示利润，够算现金时先显示现金，不再因为一个高级字段为空而锁住整张结果页。未知仍保持空白，不用 `0` 伪装已知事实。
5. 创业预估的保守、基准和乐观三档由基准完成量与最大产能自动生成，用户不需要手填三遍销量。
6. 点击“保存本次结果”后先看摘要，再点击一次“确认保存”。这会新建一份不覆盖历史的本地记录；旧版详细核算仍可读取，但不会被新版改写。

核算保存后，同一页面会进入第二步“制定本月盈利目标”。用户填写扣除全部成本和自己合理工资后希望真正赚到的月利润；系统保留自动保本线，并确定性计算盈利营业额、交付量、现金保底和成交目标。销售收款与利润交付独立建模，不把成交、到账、确认收入或交付量互相复制。

未保存输入只是本机临时草稿，不进入首页和经营事实层。确认保存后，公式结果才回流首页的“算账结论”；没有核算记录时，首页只提示完成首次算账，不摆放一排伪空指标。

AI 可以帮助补齐待填数据、解释利润与现金的差异，并在已保存结果上提出一个最大问题和一个动作。数字由本地固定公式计算，AI 不能改写公式结果。核算输入变化后，与旧数据绑定的 AI 结论必须失效。

## 盈利目标倒推

目标方案由计算页调用固定公式生成，用户查看摘要并确认后保存；AI 对目标方案永久只读。经营助手随后逐轮确认当前实收、成交、确认收入、交付量、剩余经营日和转化依据，通过受限的只读脚本生成漏斗、每日任务、当前差额和一个“本周先做”。

- 单位贡献不为正时不生成伪目标，先处理定价或直接成本。
- 盈利交付目标超过稳定产能时停止扩大获客，先调整价格、成本、交付方式或产能。
- 转化率完全未知时进入七天校准，不使用行业默认数据。
- 渠道占比和周权重必须合计 100%；冲刺系数默认 `1.00` 并单独展示。
- 核算哈希变化后旧目标退出首页；目标哈希变化后旧行动计划退出首页，但历史记录不删除。

## 两条经营路径

1. 已经有真实客户或项目：AI 核实事实门和六字段，整理项目卡、回款状态与唯一下一步。
2. 有能力但服务还没标准化：AI 把能力整理为**待验证方案**和一个验证动作；只要事实门尚未通过，就不能称为项目，也不能把价格假设计入报价或收入。

AI 会读取现有 Markdown 后自动分流，不让用户自己选表单。每轮只主动追问 1—3 个高价值问题；信息足够后先展示“看板草稿”和一条经营建议，用户敲定后再展示**一次**目标文件与逐字写回预览。用户针对当前预览用自然语言明确同意即可写入，例如“确认”“可以写”“就按这个”“执行吧”，不要求背固定口令。若预览内容被修改，才需要对新预览再确认一次。写入、复读成功后，首页顶部会显示同步反馈并自动更新。

## 金额判断口径

- 价格设想、试卖想法和 `planned` 验证记录都不算真实报价。
- 报价不等于收入，也不等于客户已经接受的应收；只有合同、客户确认或明确付款安排支持的金额才可称为应收。
- 没有实际回款只说明现金尚未到账，不能单独推出利润；已有回款也只能证明现金进账，不能把到账直接当利润。
- 明确待收只统计有客户接受证据的应收减去对应到账；只有报价而没有接受证据时显示“未知／待确认”，不得机械相减。
- 保存核算后，首页才可使用结构化成本判断可持续利润；报价、回款和核算利润仍是三种不同口径。
- 老板合理工资计入利润成本；现金结果只看经营账户实际流入和实际流出，实际取款应包含在现金流出中，不能用合理工资替代真实现金动作。

## AI 边界

- AI 以运营为主，不替用户选择行业或战略。
- AI 必须区分用户事实、待验证假设、外部证据和 AI 建议。
- AI 修改前必须展示一次目标文件和逐字拟写内容；用户针对当前预览自然语言明确同意后才能写回。
- AI 只能写白名单 Markdown，不删除、不移动、不批量重命名文件，不修改首页、专家内核、插件和系统配置。
- “创业算账”不等待 AI 写回；用户在计算页点击“确认保存”，即只授权新建当前这份核算快照。
- 盈利目标同样由计算页一次确认创建；AI 不能创建、编辑或覆盖目标，只能经预览确认后追加确定性复算通过的行动计划。
- Claudian 保持 `normal + Safe`（配置字段为 `acceptEdits`）；不建议使用 YOLO 或自动放行全部操作。
