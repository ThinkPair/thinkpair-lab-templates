# 数据与统计规则

## 一条记录一个 Markdown

每一项正式数据都单独保存为一个 Markdown 文件。练习、证据和复盘不会继续追加在同一个滚动文件里，也不会用 bullet 数量冒充能力提升。

所有正式记录都包含以下共同字段：

```yaml
record_id: "全局唯一记录编号"
record_type: "记录类型"
skill_id: "所属主技能编号"
record_status: "draft | confirmed | archived | demo"
created_at: "YYYY-MM-DDTHH:mm:ss+08:00"
updated_at: "YYYY-MM-DDTHH:mm:ss+08:00"
privacy: "private | sensitive | shareable"
schema_version: "ability.v1"
```

## 正式记录类型

| `record_type` | 用途 | 保存位置 |
|---|---|---|
| `skill_profile` | 一项主技能、目标成果和当前能力版本 | `20_能力地图/主技能.md` |
| `skill_dimension` | 六个维度的定义、证据标准和当前证据状态 | `20_能力地图/能力维度/` |
| `practice_record` | 一次练习的目标、过程、结果与下一调整 | `30_刻意练习/练习记录/` |
| `evidence_item` | 作品、对比、评价、证书或过程证据 | `40_证据与反馈/` |
| `skill_review` | 周期复盘、最大差距和下一练习 | `50_能力复盘/复盘记录/` |
| `capability_transfer` | 经用户确认的能力移交候选 | `60_双工具交换/能力移交卡/` |
| `market_feedback` | 商业工具返回的脱敏市场反馈 | `60_双工具交换/市场反馈/` |

## 统计门

- 仅统计 `record_status: confirmed`。
- `draft` 是尚未确认的草稿，不能参与任何能力结论。
- `demo` 只用于学习结构，永远不能进入真实首页统计。
- `archived` 只保留历史，不进入当前首页。
- 模板文件即使含有字段，也保持 `draft` 且关键编号为空，不进入统计。
- 练习次数、投入时长和连续天数只能描述行为，不能单独证明能力升级。

## 主技能唯一性

当前主技能必须同时满足：

```yaml
record_type: skill_profile
record_status: confirmed
status: active
```

同一时间只能存在一条符合条件的记录。启用新主技能前，必须先把旧主技能的 `status` 改为 `inactive` 或完成归档，并在预览中同时展示两处变更。

首页读取的核心字段固定为：

- `skill_profile`：`skill_name`、`target_outcome`、`ability_version`、`status`。
- `skill_dimension`：`dimension_name`、`dimension_order`、`success_criteria`、`evidence_state`、`evidence_refs`。
- `practice_record`：`practice_goal`、`dimension_id`、`result`、`next_adjustment`。
- `evidence_item`：`evidence_type`、`title`、`source`、`summary`。
- `skill_review`：`biggest_gap`、`next_practice`。
