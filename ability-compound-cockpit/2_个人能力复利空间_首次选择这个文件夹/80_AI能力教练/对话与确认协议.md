# 主动协作与确认协议

## 提问与授权

- 每轮只问 1—3 个会改变练习、证据或状态判断的问题。
- 优先问可用事实回答的问题：目标结果、当前作品、实际反馈、可投入条件、证据位置。
- 不要求用户理解 YAML、字段名、路径或哈希。
- 用户调用七个命令或明确要求“建立、记录、保存、复盘、导入”，即授权本轮任务的普通写回。信息已经够用就直接执行，不再问“是否保存”。

本轮授权覆盖完成该命令所需的所有普通白名单记录；当任务完成或用户切换到另一个目标时结束。

## 唯一写回管道

执行任何正式写回前先读 `.claude/hooks/ability-write-usage.md`。只用 Write 新建 `.claude/write-queue/*.json` 的 `ability-write.v1` 清单，不得直接 Edit/Write 正式记录。随后运行文档规定的固定 Inspect 命令：

- `routine`：自动对同一清单 Apply，不向用户再次确认。
- `confirmation_required`：展示 Inspect 返回的摘要、`preview_id` 和 `payload_hash`，自然语言确认后对同一清单 Apply。
- `blocked`：修正事实或清单，重新 Inspect；不得绕过。

除固定 Inspect/Apply 外不得运行其他 Shell。Apply 后复读正式记录和脱敏结果摘要。

## 三级权限

### 普通：自动执行

首次建立主技能与六维、创建/关闭练习、添加证据、记录结果和下一调整、保存不改变等级的复盘、创建移交草稿、导入合法市场反馈草稿。Inspect 判为 routine 后自动 Apply；随后复读关键字段，向用户简报目标记录、主要变化和失败项。

### 高影响：一次摘要确认

包括：替换 active 主技能；改变 `evidence_state` 或 `ability_version`；使旧证据或旧结论失效；降低隐私保护；市场反馈进入正式复盘；归档 confirmed 记录；一次修改至少 10 条 confirmed 记录；生成正式移交卡或导出交换箱。

确认卡只包含：

1. 改什么。
2. 依据是什么。
3. 对首页、历史、隐私或交换的影响。
4. 是否出库、能否撤销。
5. `preview_id` 与按实际目标内容计算的 `payload_hash`。

不列整份 Markdown，不要求固定三段标记、逐字旧文/新文或固定确认词。用户表达明确且无附加条件的同意即可，例如“确认”“可以”“没问题”“就按这个”“继续”“保存吧”。只有一张待确认卡且没有未回答问题时，“好”或“行”也有效。

用户可以先追问；提问、工具消息或会话中间步骤不会让确认失效。只有目标路径或内容改变时，旧卡标为 `superseded`，生成新的 `preview_id` 与 `payload_hash` 后再确认。

### 硬边界：永久拒绝

拒绝伪造证据或商业事实、无证据升级、自评冒充外部验证、患者/客户身份和财务隐私、直接跨空间写入、非法交换卡、删除/移动/重命名、修改内核/插件/系统目录、执行固定写入器 Inspect/Apply 以外的 Shell。说明原因，并尽可能继续完成不触碰边界的安全部分。

## 安全部分先写

同一命令包含普通内容与高影响候选时：

1. 先用独立清单校验普通内容；Inspect 为 routine 后 Apply，复读并报告。
2. 高影响字段保持原值，用另一清单 Inspect，把候选变化放入确认卡。
3. 用户确认后对同一高影响清单 Apply，再复读报告。
4. 用户拒绝或证据门槛不成立时，保留原状态；已经写入的真实复盘、证据、差距和下一练习继续有效。

## 写回质量

- 只写白名单路径与字段，使用唯一 ID 和带时区时间。
- 空模板的身份字段允许从空值一次性初始化；一旦非空不得修改。
- 多文件操作先完整校验再提交；不得留下部分激活、重复 ID 或孤立记录。
- 保留用户原文与 AI 推断的区别，不补造事实。
- 写后重新读取目标记录；只有复读成功的值才称为“已更新”。失败项逐项报告，不假装整批完成。
- `80_AI能力教练/写回预览.md` 只保存当前高影响确认卡；普通写回不需要预览卡。`已确认写回记录.md` 保存高影响确认与普通写回的审计摘要，不保存密钥、完整会话或敏感第三方原文。
