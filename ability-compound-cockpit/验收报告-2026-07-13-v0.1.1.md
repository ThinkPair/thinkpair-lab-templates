# v0.1.1 AI 主动协作写回修复验收报告

## 结论

v0.1.1 已修复首次建档和日常记录被自定义守卫反复拒绝的问题。权限模型改为“普通写回自动执行、高影响变化一次摘要确认、违法或破坏性动作永久拦截”，并由确定性写入器统一校验、落盘和回滚。测试副本真机已完成当前模型主持的 `/skill-start` 七文件建档与首页回流。初次验收结束时曾错误地把测试副本七文件恢复为空模板；用户指出后，已从原确认会话恢复“商业运营思维咨询辅导”及六维，永久母版仍保持空白。

本轮修复已经通过自动化和真机验收，可以作为 v0.1.1 release candidate。仍未完成的是一名真实目标用户的 30—60 分钟完整闭环：练习、证据、反馈、复盘和正式能力移交；这项种子验证继续保留，不写成已经通过。

## 真实故障与根因

- 用户测试会话中共有 61 次 Write/Edit 尝试，成功 0 次；没有半写入和正式数据污染。
- 旧守卫同时要求固定确认词、严格相邻消息、完整 Markdown 三标记、old/new 逐字匹配，并禁止修改空模板中又必须初始化的身份字段。
- “空模板必须初始化”与“身份字段禁止修改”形成首次建档死锁；YOLO 不能绕过自定义守卫，因此不是用户操作问题。
- 两张原始截图和脱敏故障报告保存于 `10_Sources/原始材料/产品测试/个人能力复利驾驶舱写回失败-2026-07-13`，标记为 `privacy: sensitive`。

## 主动协作权限

- `/skill-start` 在空白空间直接建立一项主技能和六个维度；只有替换现有 active 主技能才确认。
- 练习计划、练习关闭、证据添加、结果和下一调整、无升级复盘、能力移交草稿、市场反馈草稿均自动写回，不再追问“是否保存”。
- 能力状态或版本变化、旧证据失效、降低隐私、正式纳入市场反馈、至少 10 条 confirmed 批量变更、正式生成或导出能力移交卡，只确认一次。
- 确认只展示变化、依据、影响、出库／撤销信息和 `preview_id + payload_hash`；一般自然语言同意有效，提问不会让预览失效。
- 伪造证据或商业事实、无证据升级、自评冒充外部验证、身份／财务隐私泄露、直接跨空间写入、非法交换、删除移动重命名、修改内核／插件／系统目录和任意 Shell 继续硬拦截。
- 某个等级变化不满足条件时，只保留该字段原值；复盘、证据和下一练习等安全内容仍可写入。

## 确定性写回引擎

- 新增 `ability-write.v1` 批次清单和 Windows PowerShell 写入器；AI 提交完整目标内容，写入器独立判断 `routine / confirmation_required / blocked`。
- 写入器统一校验路径、`ability.v1` schema、固定六维、唯一 active 主技能、唯一当前练习、证据阶梯、交换边界和内容哈希。
- 多文件写回先全量校验，再临时落盘，最后整体替换；中途异常会回滚，重复执行不会产生第二组记录。
- `record_id / skill_id / dimension_id / created_at` 仅允许在空模板中初始化一次，初始化后保持不可变。
- `AUTO_NOW` 在检查阶段转换为本地 ISO 时间；更新记录保留原 `created_at`。
- AI 只能投递批次并调用固定写入器，不能自行把高风险动作声明成普通写回。
