# 小微服务生意经营诊断 Agent｜本地 Web 与直播实验合同 v0.1

> [!warning] 2026-08-07 已降级
> 本地实现和QA仍作为历史证据保留，但未发生直播实测、真实采用或收费，不再进入当前产品推进。见[[70_Governance/未变现项目降级与根库瘦身清单-2026-08-07]]。

> 当前状态：**本地Web第一版已实现并通过本地浏览器验收，直播尚未实测。** 本合同锁定第一版的产品逻辑、画面和证据门；不把本地技术通过写成正式商业交付，不把直播注意写成需求成立。

## 一句话产品定义

让小微服务生意经营者先确认问题是不是真的存在、发生在外部市场还是内部经营，再得到有证据边界的根因判断和一个优先动作。

## 黄金圈

### WHY｜为什么做

> **经营不是上来就给方法，而是先证明问题到底在哪。**

小微经营者缺的往往不是更多方法，而是判断自己究竟遇到了什么问题。一个连问题是否真实、是市场变化还是经营问题都没验证过的建议，会让经营者拿时间和真金白银为错误判断买单。AI应先帮助用户把事实问清楚，再参与判断。

### HOW｜如何实现

```text
用户描述经营困惑
→ 验证问题是否真实存在
→ 区分外部市场变化与内部经营问题
→ 证据不足继续追问／保留未知
→ 证据足够后形成根因候选和置信度
→ 给出一个优先动作及验收方式
```

AI负责逐轮提问、结构化整理和必要工具调用；运营问题库与判断规则决定问什么、为什么问、何时不能下结论；经营者负责提供事实、纠正信息并决定是否采用建议。

### WHAT｜做成什么

一个本地运行的经营诊断网页。第一版只跑通“客户为什么越来越少”这一条诊断链，并生成一份可在直播中完整展示的诊断报告。

## 第一版唯一问题

> **客户为什么越来越少？**

这里的“客户少”必须继续拆分为：

- 来客／咨询人数减少；
- 成交订单减少；
- 营业额下降；
- 客单价下降导致的营业额变化；
- 老客复购下降；
- 用户主观感觉，但暂无同口径记录。

不得把以上对象混成一个结论。

## 诊断阶段

### 阶段1｜验证问题是否成立

首轮取得：

- 生意类型；
- 城市级区域或脱敏经营半径；
- 用户认为发生的问题；
- 变化开始时间；
- 比较周期；
- 客户数、订单数、营业额、客单价中有哪些真实记录；
- 营业时间、产品、渠道、价格是否同期变化。

若只有感受、没有可比信息，页面必须输出：

> 当前只能确认你感受到客户减少，证据不足以确认客户真的减少。下一步先补齐最关键事实。

### 阶段2｜判断外部盘与内部盘

#### 外部盘候选

- 经营半径与主要客群；
- 人口、商圈、交通和客流变化；
- 同类竞品增减；
- 需求季节性；
- 平台、渠道与入口变化；
- 行业／政策／区域公共信息。

#### 内部盘候选

- 曝光与触达；
- 咨询、到店与线索；
- 成交转化；
- 老客复购；
- 产品、价格与套餐；
- 服务、交付和口碑；
- 营业时段、渠道承接和人员动作。

第一版本不要求自动获得全部外部数据。外部证据可以使用明确标记的演示卡或手动录入，但不得伪装成已经联网取得的实时事实。

### 阶段3｜形成诊断

页面至少输出：

1. 问题是否已确认；
2. 已确认事实；
3. 未知信息；
4. 外部变化证据；
5. 内部变化证据；
6. 当前最可能根因；
7. 其他替代解释；
8. 判断置信度；
9. 仍需补问的关键问题；
10. 一个优先动作及短周期验收方式。

## 页面最小结构

1. **信念首页**：主标题“先别急着改经营，先确认问题到底在哪”；
2. **问题输入**：自然语言描述＋最少背景；
3. **逐轮追问**：每屏1—3个高价值问题，不一次抛出长问卷；
4. **证据台账**：已知／未知、外部／内部、事实／假设分栏；
5. **诊断报告**：根因候选、置信度、替代解释、唯一动作；
6. **演示重置**：一键回到空白案例，便于直播重复演示。

## 今晚本地样子货的真实与虚构边界

### 必须真实运行

- 问题分支随回答变化；
- 信息不足时继续追问；
- 外部盘和内部盘分开；
- 未知不按0、不强行补齐；
- 报告不是固定文案；
- 最后只保留一个优先动作。

### 可以暂缓

- 登录、账号和权限系统；
- 支付、会员和订阅；
- 正式数据库；
- 用户自配API界面；
- 全自动联网取证；
- App、U盘打包和跨行业题库；
- 完整六母型与历史163题题库；
- 公网部署。

### 严禁伪装

- 不把演示外部数据说成实时搜索；
- 不把模拟商户说成真实客户；
- 不把固定样例报告说成AI已完成诊断；
- 不展示API Key、本地绝对路径、私人知识库、浏览器私密标签或第三方身份；
- 不承诺照做必赚、必增长或诊断等于专业审计。

## 直播四画面｜用户已确认

### 画面1｜WHY：人物＋信念

- 今天唯一问题：“客户越来越少，到底是市场变了，还是经营出了问题？”
- 固定信念：“经营不是上来就给方法，而是先证明问题到底在哪。”

### 画面2｜HOW：诊断操作

- 网页占主要画面；
- 人物保留小窗；
- 每次回答后解释为什么下一问改变；
- 不长时间展示代码和安装过程。

### 画面3｜HOW：证据判断

- 放大已知／未知；
- 展示外部盘／内部盘；
- 解释为什么当前不能下结论，或为什么根因候选发生变化。

### 画面4｜WHAT：诊断报告

- 展示根因、依据、边界、置信度和一个优先动作；
- 收口请求观众提交匿名行业、城市级区域、变化周期和最担心的原因。

## 本场直播唯一实验

```yaml
hypothesis_id: micro-service-diagnosis-agent-live-001
stable_capability: 把模糊经营问题转为事实验证、外部/内部判断、根因与一个动作
target_actor: 有真实经营责任的小微服务生意经营者
production_node: 判断客户减少原因并决定下一步经营动作
problem_and_cost: 把市场变化误判为经营问题，或把经营问题误判为市场问题，导致错误投入
live_question: 客户为什么越来越少
proof_object: 本地Web诊断链＋证据台账＋诊断报告
changed_variable: 从泛运营讲解改为一边讲逻辑一边操作诊断网页
intended_next_action: 主动说明自己的行业与经营问题，或请求匿名试跑
primary_metric: 主动经营询问与匿名材料提交
target_evidence_level: E3-E4
```

## 直播证据判定

| 观众行为 | 当前解释 |
|---|---|
| “工具很厉害” | E1—E2注意或理解，不证明经营需求 |
| “用的什么AI” | 工具兴趣，不自动算目标客户 |
| 描述自己的行业和客户问题 | E3具体问题 |
| 主动问“能不能给我的店试一下” | E3向E4推进 |
| 愿意提交匿名经营事实或约时间试跑 | E4行动承诺 |
| 实际使用并回访动作或结果 | E5生产使用 |
| 主动问价、付费试用或明确有价委托 | E6结算验证 |

本场不要求E6，但必须如实记录是否出现；没有就写0或unknown。

## 成熟对标的模块化借鉴

- **HubSpot Website Grader**：成熟诊断入口，2006年起累计评估数百万网站；借鉴“先让用户得到自己的诊断，再进入方法和产品”，不复制SEO评分。
- **Neil Patel／Ubersuggest**：以“让小公司也能竞争”的信念持续做免费内容，再由工具承接操作；借鉴信念—内容—工具一致，不复制SEO产品。
- **Pieter Levels／Hoodmaps**：2017年公开直播从零制作，观众立即使用并贡献数据；借鉴公开制作与实时反馈，不把技术受众等同于本项目客群。
- **黄金圈**：WHY是信念，HOW是把信念做出来的独特行动，WHAT是实际产品；本项目用信念开场、诊断过程证明、网页承接。

近期AI工具爆款只作为标题、魔法时刻和画面呈现参考，不作为长期商业路径已经成立的证据。

## 当前验收门

第一版本只有同时满足以下条件才可称为“本地原型完成”：

1. 在本机浏览器可打开；
2. 能从问题输入走到报告；
3. 至少两组不同回答会走出不同追问或结论；
4. 证据不足时明确停止或继续追问；
5. 外部／内部、事实／未知可见；
6. 报告只给一个优先动作；
7. 刷新或重置可重新演示；
8. 直播画面中字体可读；
9. 无真实密钥、个人隐私和未标记的模拟结果；
10. 未实播前保持`validation_status: untested`。

2026-08-04 23:49本地验收结果：以上10项本地原型门均满足；其中第10项继续生效，真实直播与市场验证状态仍为`untested`。详细证据见[[本地Web原型验收记录-2026-08-04]]。
