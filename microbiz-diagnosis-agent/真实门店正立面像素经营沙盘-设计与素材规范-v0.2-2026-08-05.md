# ThinkPair｜真实门店正立面像素经营沙盘设计与素材规范 v0.2

> 当前状态：**网站设计与素材合同已整理，视觉方向待“一店五状态”样张验证；网页实现仍在进行，不能写成新视觉已经完成或获得市场验证。**

## 一句话产品画面

以真实门店为原型建立一座可变化的正立面像素店铺；AI 每获得一个经营事实，店铺、街区、顾客、竞品和问题标记就发生对应变化，最后把“问题在哪里、依据是什么、下一步验证什么”收束为一张经营沙盘。

这不是给文字报告套像素外壳，而是建立一套可视化经营语言：

> **店铺是主体，人物与街区是数据，场景变化是证据，诊断才是结论。**

## 一、稳定产品逻辑

### WHY｜为什么做

经营者缺少的往往不是更多方法，而是判断问题究竟有没有发生、发生在外部市场还是内部经营。长报告和复杂知识库要求用户主动阅读、维护和理解系统，容易与行动型、非长文本型经营者的使用习惯错位。

### HOW｜如何诊断

```text
用户描述经营困惑
→ AI 建立店铺与经营画像
→ 用同口径事实验证问题是否成立
→ 区分外部盘变化与内部经营问题
→ 证据不足继续追问并保留未知
→ 形成根因候选、替代解释和置信边界
→ 只给一个优先验证动作
→ 回收7天／30天结果
```

### WHAT｜做成什么

一个以像素经营世界承载问诊的本地 Web 原型。第一版仍只跑通一个虚构店铺和“客户为什么越来越少”一条诊断链，不扩登录、支付、会员、App、U盘量产或完整行业题库。

## 二、三幕体验结构

### 第一幕｜建店

- 左侧 AI 对话，右侧固定正立面店铺；
- 店名、城市级区域、行业、面积、经营年限、员工数量等事实逐步改变店铺；
- 用户可从空立面看到门头、入口、窗户、座位、员工和经营设施逐层建立；
- 回答必须改变场景，不只把答案保存为文字。

### 第二幕｜诊断

- 建店完成后，镜头向外展开经营半径和周围街区；
- AI 根据回答继续显示客流、进店、咨询、成交、复购、竞品和成本变化；
- 外部盘与内部盘同时可见，但不能把未取得的公共数据伪装成实时联网结果；
- 已确认事实、可能解释和待核实信息采用不同视觉语法。

### 第三幕｜判断

- 街区与店铺收束为经营沙盘；
- 六边图、根因、外部／内部证据、替代解释和唯一动作必须能回指前两幕出现过的对象；
- 未知保持“待核实”，不用0补齐，不生成虚假评分；
- 诊断结果不是终点，后续必须记录动作及7天／30天反馈。

## 三、视觉语言

### 当前主风格

- `photo-referenced architectural facade pixel art`
- `straight-on front elevation`
- `orthographic architectural view`
- 真实门店结构＋像素插画重绘；
- 固定正面或轻微平视，建筑完整居中；
- 米白、木色、砖红、灰绿等低饱和成人配色；
- 深棕或深灰像素轮廓，细节清楚但不杂乱；
- 招牌区域留白，店名由网页叠加。

### 明确排除

- Minecraft、体素3D、等距房间；
- 儿童卡通农场和高饱和手机游戏；
- 直接对照片套马赛克滤镜；
- 乱码招牌、品牌复刻和水印；
- 只有气氛、不能映射经营事实的霓虹装饰；
- 每张图改变镜头、比例、光线和像素密度。

## 四、素材系统

| 素材层 | 内容 | 是否固定 | 主要作用 |
|---|---|---:|---|
| 建筑底层 | 外立面、门窗、入口、雨棚、空调 | 是 | 建立“这是同一家店” |
| 店铺装饰 | 招牌、绿植、桌椅、橱窗、灯光 | 可变 | 映射店型与经营阶段 |
| 环境层 | 道路、住宅、写字楼、学校、竞品 | 可变 | 表达经营半径与外部盘 |
| 人物层 | 路人、新客、老客、员工 | 可变 | 表达人流、进店、成交与复购 |
| 经营对象层 | 商品、收银、库存、座位、服务点 | 可变 | 表达内部流程与产能 |
| 诊断层 | 半径、路线、实线、虚线、空心标记 | 可变 | 区分事实、推测和未知 |
| 结果层 | 六边图、根因卡、唯一动作 | 可变 | 收束判断，不替代证据 |

### 四类问题的画面表达

1. **客流下滑**：路过人数、进店人数、经营半径、周边人口与竞品变化；
2. **成交卡住**：顾客停留、咨询、试用、收银和离店路径中的流失位置；
3. **复购下降**：新客与老客区分、回店周期、会员或售后路径中断；
4. **利润被挤压**：收入进入与房租、人工、物料、平台抽佣、库存等成本流出。

## 五、动态实现原则

动态不依赖整段 AI 视频或大量 GIF。建筑底图保持稳定，可移动对象拆层后由网页状态驱动：

- 顾客4—8帧走路、进店、掉头、排队；
- 门开关、招牌亮灭、橱窗和座位状态变化；
- 竞品出现、客流变稀、路线分流；
- 经营半径扩大或缩小；
- 已确认用实体／实线，可能解释用半透明虚线，待核实用空心扫描标记；
- 优先使用透明 PNG／WebP、Sprite Sheet 与 CSS／GSAP 的 `transform`、`opacity`、`scale`、`steps()`。

原则是：**AI 生产原创场景资产，网页状态机让经营变化发生。**

## 六、照片转像素母提示词

```text
任务：将真实门店照片重绘为正立面建筑像素插画，用于经营诊断网站。

结构参考：严格保留原照片的楼层数量、门窗位置、立面宽高比例、招牌位置、雨棚、空调、植物和入口关系；不要擅自增加楼层、门窗或其他建筑。

视觉风格：photo-referenced architectural facade pixel art, straight-on front elevation, orthographic architectural view；日系街景建筑像素插画；清晰深棕色像素轮廓；低饱和米白、木色、砖红和灰绿配色；精致、克制、面向成年经营者；不是 Minecraft，不是霓虹赛博朋克，不是照片马赛克滤镜。

画面规范：完整门店居中，四周保留10%安全留白；固定正面视角，不使用广角、俯视或等距视角；背景使用纯色 #E9E5DC；招牌区域保留为空白；不出现人物、车辆、水印和品牌标志；适合作为网站独立场景资产。
```

状态变体不得重新发明建筑，只允许改变指定图层。例如“客流下滑”只改变路人数量、进店轨迹、门前停留和诊断标记；门窗、比例、镜头、时间与基础配色保持不变。

## 七、资产生产门禁

不要先批量生成上百张。第一轮只完成“一店五状态”证明集：

1. 咖啡店基础立面；
2. 正常经营；
3. 客流下滑；
4. 成交卡住；
5. 复购下降；
6. 利润被挤压；
7. 两种顾客角色和门／招牌／排队等最小动态部件。

通过标准：同一店铺结构稳定；不看长文字也能识别经营变化；推测没有被画成事实；网页可独立控制人物和标记；横屏网页与9:16视频均有安全构图。证明集通过后才扩行业。

## 八、账号、直播、网站与视频连贯

- **账号**：持续提出一个经营者能识别的问题，不把“像素”和“AI”当定位；
- **直播**：现场建店、追问、显示证据和形成判断；
- **网站**：经营者亲自建立店铺并尝试诊断；
- **短视频**：复用同一店铺和状态机，录制为一个问题的像素经营案例；
- **深度咨询**：对愿意提交脱敏材料的经营者继续核账和复盘；
- **数据闭环**：经营画像→问题→证据→判断→动作→7天／30天结果。

对外一句话建议保持：

> **把一家生意搭出来，用事实判断问题到底出在哪里。**

像素风是降低理解门槛的表现机制，不是产品承诺。更多访问不会自动让诊断更准；只有结构化、可比较、经同意并带结果回访的数据，才能改善问题路由、行业基线与动作有效性。
